# Патентный радар — пользовательские сценарии

> **Статус: КТ1 (2026-10-07).** Сценарии описывают поведение интерфейса. На КТ1 их проходят в кликабельном прототипе: в режиме `mock` ответ формирует локальная функция поиска по моку [`frontend/src/mock/search.json`](../../frontend/src/mock/search.json), в режиме `api` — заглушка `POST /search` бэкенда; обе ведут себя одинаково. Поиск по корпусу и языковая модель на КТ1 не работают; где это важно, в сценарии есть пометка.

Обозначения: в «кавычках» — точные строки интерфейса и ответа API (интерфейс показывает их без кавычек); `моноширинным` — поля контракта API, маршруты и вводимые значения. Контракт API — [`spec/tech/architecture.md`](../tech/architecture.md), описание продукта — [`spec/product/product.md`](product.md).

## 1. Экраны и состояния

| Экран или состояние | Маршрут | Когда показывается |
|---|---|---|
| «Экран запроса» | `#/` | при открытии приложения; по кнопке «Изменить запрос» |
| подсказка «Слишком короткий запрос» | `#/` | при попытке поиска с запросом короче 3 слов |
| «Загрузка» | `#/results?…` | запрос отправлен, ответа ещё нет |
| «Выдача» | `#/results?…` | ответ получен, `results` не пуст |
| «Ничего не найдено» | `#/results?…` | ответ получен, `results` пуст |
| «Сервис недоступен» | `#/results?…` | режим `api`: сервер не ответил, ответил кодом 5xx или ответ нельзя разобрать |
| «Запрос отклонён» | `#/results?…` | API ответил кодом 422; в режиме `mock` так же отвечает мок — например, если ссылку `#/results?…` открыли с запросом короче 3 слов |
| «Карточка патента» | `#/patent/<id>` | по ссылке из «Выдачи» |
| «Патент не найден в текущей выдаче» | `#/patent/<id>` | записи с таким `id` нет в последнем полученном ответе (например, страницу открыли по прямой ссылке) |

Общие правила:

- Параметры маршрута `#/results?…` называются так же, как поля запроса API: `query` и `top_k` пишутся всегда, `year_from`, `year_to` и `ipc` — только если заданы. Данные для этого маршрута запрашиваются по его параметрам, поэтому кнопка «Назад» браузера и «Назад к выдаче» возвращают ту же выдачу.
- Во всех состояниях маршрута `#/results?…` вверху видны строка «Запрос» с текстом запроса и строка фильтров. Строка фильтров перечисляет заданные фильтры с их подписями («Год публикации: с 2022», «МПК (префикс): A01G») и всегда — «Количество результатов: 10» или выбранное значение; разделители — на усмотрение вёрстки.
- Кнопка «Изменить запрос» есть на «Выдаче» (рядом со строкой «Запрос»), в состояниях «Ничего не найдено», «Сервис недоступен», «Запрос отклонён» и «Патент не найден в текущей выдаче» (среди действий состояния) — на каждом экране одна. Она открывает «Экран запроса» с текстом и фильтрами текущего запроса.
- Плашка «Демонстрационные данные: записи DEMO-xxx — не реальные патенты. Результаты — не юридическое заключение.» видна на «Выдаче» и в «Карточке патента», если хотя бы у одной показанной записи `id` начинается с `DEMO-`. Отдельного поля для этого в ответе API нет.
- У номера каждой записи с префиксом `DEMO-` в «Выдаче» и «Карточке патента» стоит бейдж «ДЕМО» (подсказка при наведении — «Демонстрационные данные»).
- На всех экранах в шапке — заголовок «Патентный радар» и индикатор прототипа «режим данных» со значением `mock` или `api`; в подвале — дисклеймер «Это первичный поиск аналогов, а не юридическое заключение о новизне или патентоспособности.»
- Похожие патенты показаны карточками: на телефоне — в одну колонку, на планшете — в две, на широком экране — списком рядом со «Сводкой». Горизонтальной прокрутки страницы нет ни на какой ширине.
- Тема интерфейса тёмная по умолчанию; кнопка в шапке включает светлую (например, для проектора) и обратно, выбор запоминается после перезагрузки.
- Смена экрана сопровождается плавным появлением содержимого, карточки выдачи появляются по очереди, на «Экране запроса» вращается развёртка радара. Если в системе включено «уменьшить движение» (`prefers-reduced-motion`), анимаций нет.

## 2. Основной сценарий: от описания идеи до карточки патента

**Цель.** Пользователь описывает идею своими словами, получает похожие патенты с пояснением, открывает карточку одного из них и возвращается к выдаче.

**Предусловия.**

- Приложение запущено; на КТ1 — `npm run dev` в папке `frontend/` (режим `mock`, бэкенд не нужен), адрес http://localhost:5173/.
- Фильтры в значениях по умолчанию: «Год публикации» не задан, «МПК (префикс)» пуст, «Количество результатов» — 10.

**Шаги.**

| № | Действие пользователя | Реакция системы | Что видно на экране |
|---|---|---|---|
| 1 | Открывает приложение | открывается маршрут `#/` | «Экран запроса»: анимированный радар (декоративный: луч вращается, «цели» вспыхивают); крупный заголовок «Патентный радар»; вводный текст «Опишите идею изобретения своими словами — радар найдёт похожие патенты РФ и кратко объяснит, чем они похожи на вашу идею и чем отличаются.»; поле «Описание идеи» с подсказкой «Опишите своими словами: что это, из чего состоит и как работает», внизу поля — счётчик «0 / 2000» и кнопка «Найти аналоги»; блок «Примеры запросов» из 4 кнопок, под подписью каждой мелко показан текст примера; блок «Фильтры» |
| 2 | Описывает идею в поле или нажимает пример «Полив по влажности почвы» | текст примера подставляется в поле; поиск не запускается | в поле — «Хочу, чтобы грядки на даче поливались сами: датчик в земле замечает, что почва пересохла, и включает воду, а если обещают дождь, полив не включается.»; счётчик «149 / 2000» |
| 3 | Нажимает «Найти аналоги» | проверка ввода пройдена (24 слова, 149 символов); переход на `#/results?query=…&top_k=10`; отправляется запрос `{"query": "…", "top_k": 10, "year_from": null, "year_to": null, "ipc": null}`; в режиме `mock` ответ формирует локальная функция с задержкой ~400 мс | «Загрузка»: маленький радар и «Ищем похожие патенты…», ниже — скелетоны в форме выдачи |
| 4 | Ждёт | приходит ответ с 3 результатами | «Выдача»: плашка демо-данных; строка «Запрос»; строка фильтров; блок «Сводка» из 5 абзацев; блок «Похожие патенты» со счётчиком «Результатов: 3» и карточками: DEMO-002 (12.47), DEMO-001 (9.85), DEMO-003 (4.31) |
| 5 | Читает сводку и нажимает метку `[DEMO-001]` (или карточку DEMO-001 в выдаче) | переход на `#/patent/DEMO-001` | «Карточка патента»: кнопка «Назад к выдаче»; плашка; крупный заголовок с подписью (54) Название; (57) Реферат; блок метаданных: (11) Номер `DEMO-001`, (51) МПК `A01G 25/16`, `G01N 27/22`, (45) Год публикации `2019`, «Позиция в выдаче: 2 из 3», «Оценка BM25: 9.85» и полоса релевантности; блок «Пояснение» с абзацем сводки, который начинается с `[DEMO-001]` |
| 6 | Нажимает «Назад к выдаче» (или «Назад» в браузере) | возврат на тот же маршрут `#/results?…` | та же «Выдача»: тот же запрос, фильтры, сводка и порядок строк |

**Ожидаемый результат.** Пользователь видит три похожих демонстрационных патента по убыванию оценки, читает пояснение со ссылками на номера, открывает карточку `DEMO-001` с рефератом и возвращается к той же выдаче.

**Критерии приёмки.**

- О1. На «Экране запроса» есть анимированный радар, вводный текст (раздел 5), поле «Описание идеи» со счётчиком символов, фильтры «Год публикации: с … по …», «МПК (префикс)», «Количество результатов: 5 / 10 / 20» (выбрано 10), кнопки примеров «Полив по влажности почвы», «Беспроводной датчик влажности», «Запрос без совпадений», «Слишком короткий запрос» (под подписью каждой — текст примера) и кнопка «Найти аналоги».
- О2. Нажатие на пример заменяет текст поля текстом примера дословно и не запускает поиск; фильтры не меняются.
- О3. После «Найти аналоги» сразу показывается «Загрузка» с текстом «Ищем похожие патенты…» и скелетонами, затем «Выдача»; в режиме `mock` — примерно через 400 мс.
- О4. В блоке «Похожие патенты» ровно 3 карточки в порядке DEMO-002, DEMO-001, DEMO-003. В карточке: «№ N», номер, бейдж «ДЕМО», название, «МПК» — все коды патента в порядке из `ipc`, «Год», «Оценка BM25» (12.47, 9.85, 4.31 — два знака после точки) и полоса релевантности: оценка относительно максимальной в этой выдаче. Номера, коды, годы, оценки и счётчики — моноширинным шрифтом с цифрами одинаковой ширины. На телефоне карточки идут в одну колонку, на планшете — в две, на широком экране — списком рядом со «Сводкой».
- О5. «Сводка» — отдельная выделенная панель с текстом `answer`, разбитым на абзацы по пустой строке, всего 5: вводный абзац без ссылок; абзацы, которые начинаются с `[DEMO-002]`, `[DEMO-001]`, `[DEMO-003]`; последний — «Это первичный поиск аналогов, а не юридическое заключение о новизне или патентоспособности.»
- О6. Ссылка `[ID]` в «Сводке» (ID вида `DEMO-001` или `RU<номер><код вида>`) — моноширинная метка. Если ID есть в выдаче, метка открывает его «Карточку патента»; если нет — метка некликабельна, выделена как предупреждение и показывает подсказку «Номер отсутствует в выдаче».
- О7. Щелчок по карточке выдачи (по названию или в любом месте карточки) открывает «Карточку патента». С клавиатуры карточка выбирается клавишей Tab, фокус виден обводкой всей карточки.
- О8. «Карточка патента» показывает крупный заголовок с подписью (54) Название, реферат с подписью (57) Реферат (ширина строки около 68 знаков) и отдельный блок метаданных: (11) Номер, (51) МПК, (45) Год публикации, «Позиция в выдаче: N из M», «Оценка BM25: X» в том же формате, что в выдаче (`9.85`), и полоса релевантности. На широком экране блок метаданных стоит справа, на узком — под заголовком. Коды INID — моноширинным шрифтом; значения совпадают с полями результата `id`, `title`, `ipc`, `year`, `abstract`, `score`; у номера демо-записи — бейдж «ДЕМО». Блок «Пояснение» — абзац `answer`, который начинается с `[<id>] `; если такого абзаца нет, блок не показывается.
- О9. Плашка «Демонстрационные данные: записи DEMO-xxx — не реальные патенты. Результаты — не юридическое заключение.» видна на «Выдаче» и в «Карточке патента».
- О10. «Назад к выдаче» и «Назад» браузера возвращают ту же выдачу: тот же запрос, фильтры, сводку и порядок строк.
- О11. Строка «Запрос» на «Выдаче» показывает `query` из ответа — текст пользователя без пробелов по краям.

**Экраны и состояния:** «Экран запроса» → «Загрузка» → «Выдача» → «Карточка патента» → «Выдача».

**Особые случаи.**

- Если записи с `id` из маршрута нет в последнем полученном ответе (карточку открыли по прямой ссылке, страницу перезагрузили), показывается «Патент не найден в текущей выдаче»: номер из маршрута, текст «Карточка открывается из выдачи. Выполните поиск ещё раз, чтобы снова открыть этот патент.» и кнопка «Изменить запрос». Отдельного запроса за карточкой нет: в контракте API нет метода получения патента по номеру.
- Порядок строк задаёт API: по убыванию `score`, при равенстве — по `id`. Интерфейс его не меняет; своей сортировки выдачи в прототипе нет.
- Если у патента нет абзаца в `answer` (на КТ2 модель получает рефераты только первых 5 результатов, `MAX_CONTEXT_DOCS = 5`), блок «Пояснение» в его карточке не показывается.

## 3. Альтернативные сценарии

### А1. Фильтр по году или МПК

**Предусловия.** «Экран запроса»; в поле — тематический запрос (нажат пример «Полив по влажности почвы»).

**Шаги.**

1. Задать фильтр: в «МПК (префикс)» ввести `A01G` или в «Год публикации» указать «с» `2022`.
2. Нажать «Найти аналоги».
3. Вариант «фильтр отсёк всё»: «Год публикации» с `2000` по `2010`, нажать «Найти аналоги»; в состоянии «Ничего не найдено» нажать «Сбросить фильтры».

**Ожидаемый результат.**

| Фильтры | Результаты по порядку | Абзацев в «Сводке» |
|---|---|---|
| МПК `A01G` | DEMO-002, DEMO-001 | 4 |
| МПК `G01N` | DEMO-001, DEMO-003 | 4 |
| МПК `g01n 33` | DEMO-003 | 3 |
| год с `2022` | DEMO-003 | 3 |
| год по `2020` | DEMO-001 | 3 |
| МПК `A01G` и год с `2020` | DEMO-002 | 3 |
| год с `2000` по `2010` | пусто — «Ничего не найдено» | — |

После «Сбросить фильтры» фильтры возвращаются к значениям по умолчанию, поиск сразу повторяется с тем же запросом и даёт 3 результата.

**Критерии приёмки.**

- А1.1. Префикс МПК сравнивается без учёта регистра и пробелов: `A01G`, `a01g` и `A01G 25` дают одинаковую выдачу. Патент проходит фильтр, если с префикса начинается хотя бы один его код.
- А1.2. Границы года включаются: «с 2021 по 2021» оставляет только DEMO-002. Можно задать одну границу.
- А1.3. Оставшиеся результаты идут в том же порядке, что без фильтра; колонка «№» нумерует строки текущей выдачи с 1.
- А1.4. В «Сводке» остаются вводный абзац, абзацы о прошедших фильтр патентах и дисклеймер; ссылок на отфильтрованные патенты нет.
- А1.5. Строка фильтров показывает заданные значения; «Изменить запрос» возвращает на «Экран запроса» с тем же текстом и фильтрами.
- А1.6. Если фильтры отсекли всё, показывается «Ничего не найдено» с текстом `answer`, кнопка «Сбросить фильтры» активна. Она очищает год и МПК, возвращает «Количество результатов» 10 и сразу повторяет поиск с тем же запросом.
- А1.7. Некорректные значения года не отправляются, сообщение показывается под группой «Год публикации»: год вне 1900–2100 или не целое число — «Год — целое число от 1900 до 2100.»; «с» больше «по» (например, с `2023` по `2019`) — «Начальный год не может быть больше конечного.»
- А1.8. Пустое поле «МПК (префикс)» или поле из одних пробелов — фильтр не задан, в запрос уходит `"ipc": null`. Поле не принимает больше 20 символов. Формат кода не проверяется: префикс, с которого не начинается ни один код (например, `B65D`), даёт «Ничего не найдено».

**Экраны и состояния:** «Экран запроса» → «Загрузка» → «Выдача» или «Ничего не найдено» → после «Сбросить фильтры» «Загрузка» → «Выдача».

### А2. Ничего не найдено

**Предусловия.** «Экран запроса», фильтры по умолчанию.

**Шаги.**

1. Нажать пример «Запрос без совпадений» — в поле появится «Складной зонт, у которого в ручке есть фонарик и подогрев для холодной погоды.»
2. Нажать «Найти аналоги».
3. Нажать «Изменить запрос».

**Ожидаемый результат.** После загрузки — состояние «Ничего не найдено»: заголовок «Ничего не найдено», под ним текст `answer` «Похожих патентов в корпусе не найдено. Опишите идею иначе: назначение, из чего состоит и как работает, — или ослабьте фильтры по году и МПК.» и кнопки «Изменить запрос» и «Сбросить фильтры». «Изменить запрос» возвращает на «Экран запроса» с тем же текстом и фильтрами.

**Критерии приёмки.**

- А2.1. В ответе `results` = `[]`, а `answer` — дословно текст выше, без дисклеймера; языковая модель не вызывается (на КТ2 тоже).
- А2.2. Нет карточек, блока «Сводка» и плашки демо-данных; над заголовком — радар без целей.
- А2.3. Если год и МПК не заданы, кнопка «Сбросить фильтры» неактивна.
- А2.4. «Изменить запрос» открывает «Экран запроса» с сохранённым текстом и фильтрами.

На КТ1 пустая выдача значит, что в запросе нет ни одной основы демо-темы (раздел 6); на КТ2 — что ни один документ не набрал `score ≥ MIN_SCORE` (порог подбирается на benchmark).

**Экраны и состояния:** «Экран запроса» → «Загрузка» → «Ничего не найдено» → «Экран запроса».

### А3. Слишком короткий запрос

**Предусловия.** «Экран запроса».

**Шаги.**

1. Нажать пример «Слишком короткий запрос» — в поле появится «Умный полив».
2. Нажать «Найти аналоги».
3. Дописать слово («Умный полив грядок») и снова нажать «Найти аналоги».

**Ожидаемый результат.** После шага 2 под полем — подсказка «Запрос слишком короткий. Опишите идею хотя бы тремя словами: что это, из чего состоит и как работает.»; поиск не запускается, экран и текст в поле не меняются. После шага 3 подсказка исчезает и выполняется поиск (на КТ1 — 3 демонстрационных результата).

**Правила проверки ввода.** Совпадают с проверкой в API. Интерфейс проверяет ввод при нажатии «Найти аналоги» и при ошибке запрос не отправляет; сообщение исчезает, когда поле исправлено.

| Поле | Правило | Сообщение в интерфейсе | Если запрос всё же дошёл до API |
|---|---|---|---|
| «Описание идеи» (`query`) | после обрезки пробелов по краям не меньше 3 слов; слово — непрерывная последовательность букв или цифр (`[^\W_]+` в Python, `/[\p{L}\p{N}]+/gu` в JS), знаки препинания и дефис — разделители, поэтому «Wi-Fi» — два слова | «Запрос слишком короткий. Опишите идею хотя бы тремя словами: что это, из чего состоит и как работает.» | 422 |
| «Описание идеи» (`query`) | после обрезки пробелов по краям не больше 2000 символов; поле не обрезает ввод, чтобы при вставке длинного текста ничего не терялось незаметно | «Запрос слишком длинный: сократите описание до 2000 символов.» | 422 |
| «Год публикации», поля «с» и «по» (`year_from`, `year_to`) | пусто или целое число от 1900 до 2100 | «Год — целое число от 1900 до 2100.» | 422 |
| «Год публикации», заданы оба поля | «с» не больше «по» | «Начальный год не может быть больше конечного.» | 422 |
| «МПК (префикс)» (`ipc`) | не больше 20 символов; пустое поле — `null` | не нужно: поле не принимает больше 20 символов | 422 |
| «Количество результатов» (`top_k`) | 5, 10 или 20 (API допускает 1–20) | не нужно: выбор из трёх значений | 422 |

**Критерии приёмки.**

- А3.1. Запрос из 0–2 слов (в том числе пустой, из одних пробелов или знаков препинания) не отправляется; под полем — подсказка дословно.
- А3.2. Маршрут остаётся `#/`, введённый текст и фильтры сохраняются.
- А3.3. Подсказка исчезает, когда в поле становится 3 слова и больше; следующий поиск выполняется.
- А3.4. Подсчёт слов совпадает с серверным: «Полив по влажности» — 3 слова, поиск выполняется; «Умный полив» с лишними пробелами по краям и между словами — 2 слова, подсказка.
- А3.5. Текст длиннее 2000 символов: счётчик выделен как ошибка, при попытке поиска — «Запрос слишком длинный: сократите описание до 2000 символов.», запрос не отправляется.

**Экраны и состояния:** «Экран запроса» с подсказкой «Слишком короткий запрос» → после исправления «Загрузка» → «Выдача».

### А4. Языковая модель недоступна (с КТ2)

**Предусловия.** КТ2: режим `api`, бэкенд с `LLM_PROVIDER=ollama`, Ollama не запущена или модель не скачана.

**Шаги.** Шаги 1–4 основного сценария.

**Ожидаемый результат.** «Выдача» с карточками результатов, в «Сводке» два абзаца: «Пояснение недоступно: языковая модель не ответила. Список похожих патентов ниже.» и «Это первичный поиск аналогов, а не юридическое заключение о новизне или патентоспособности.» Ответ API — 200, не ошибка.

**Критерии приёмки.**

- А4.1. «Сервис недоступен» не показывается; карточки выдачи и «Карточка патента» работают как обычно.
- А4.2. В «Сводке» нет меток `[ID]`; в «Карточке патента» нет блока «Пояснение».

На КТ1 не воспроизводится: заглушка `POST /search` языковую модель не вызывает.

**Экраны и состояния:** «Экран запроса» → «Загрузка» → «Выдача» без пояснения → «Карточка патента» без блока «Пояснение».

### А5. Ошибка сервиса

**Предусловия.** Режим `api` (`npm run dev:api`); бэкенд не запущен или отвечает ошибкой 5xx.

**Шаги.**

1. Ввести допустимый запрос (пример «Полив по влажности почвы») и нажать «Найти аналоги».
2. Запустить бэкенд и нажать «Повторить».

**Ожидаемый результат.** После шага 1 — «Сервис недоступен» с текстом «Не удалось получить ответ от сервиса поиска. Проверьте, что бэкенд запущен, и повторите попытку.» и кнопками «Повторить» и «Изменить запрос». После шага 2 — «Загрузка», затем та же «Выдача», что в режиме `mock`.

**Критерии приёмки.**

- А5.1. Сетевая ошибка, ответ с кодом 5xx или ответ, который нельзя разобрать, ведут в «Сервис недоступен». При остановленном бэкенде dev-сервер Vite отвечает на `/api/search` кодом 502. Текст запроса и фильтры не теряются.
- А5.2. «Повторить» отправляет тот же запрос ещё раз.
- А5.3. Ответ 422 ведёт в состояние «Запрос отклонён»: текст «Сервер не принял параметры запроса (ошибка 422). Проверьте текст запроса и фильтры.», кнопка «Изменить запрос». При поиске с «Экрана запроса» это состояние не появляется: ввод проверяется до отправки. Увидеть его можно по ссылке с недопустимыми параметрами, например `#/results?query=Умный+полив&top_k=10`, — и в режиме `api`, и в режиме `mock`.
- А5.4. Недоступность языковой модели — не ошибка сервиса: API возвращает выдачу без пояснения (сценарий А4).

**Экраны и состояния:** «Экран запроса» → «Загрузка» → «Сервис недоступен» → «Загрузка» → «Выдача».

Поле `abstract` нужно только «Карточке патента»; `score` показывают карточки выдачи и «Карточка патента».

Форматы значений:

- оценка — два знака после точки, как в API: `12.47`;
- год — без разделителя разрядов: `2021`;
- коды МПК — как в `ipc`: `A01G 25/16`;
- номера, коды МПК, годы, оценки и счётчики — моноширинным шрифтом с цифрами одинаковой ширины (`tabular-nums`);

- пример заменяет текст поля, не запускает поиск и не меняет фильтры;

- «Сбросить фильтры» активна, если задан год или МПК; очищает год и МПК, ставит «Количество результатов» 10 и сразу повторяет поиск с тем же запросом;
- «Изменить запрос» открывает «Экран запроса» с текстом и фильтрами текущего запроса;
- «Повторить» повторяет тот же запрос;
- «Назад к выдаче» возвращает на маршрут последней выдачи.

## 6. Как проверить сценарии в прототипе КТ1

**Запуск в режиме `mock`** (бэкенд не нужен):

```bash
cd frontend
npm install
npm run dev
```

Открыть адрес, который напечатает Vite: http://localhost:5173/. Адрес `127.0.0.1:5173` может не открыться: dev-сервер по умолчанию слушает только `localhost`.

**Особенности заглушки — это не ошибки:**

- Порядок и оценки фиксированы (DEMO-002 12.47, DEMO-001 9.85, DEMO-003 4.31) и не зависят от формулировки запроса. Пояснение составлено заранее для основного примера и одинаково для любого тематического запроса.
- Тема определяется грубо: запрос в нижнем регистре, с заменой «ё» на «е», должен содержать хотя бы одну основу из списка «полив», «влаг», «влажн», «почв», «грядк», «огород», «теплиц», «дожд», «осадк», «орош», «капельн», «пересох», «пересых». Поэтому, например, «Влагозащищённый чехол для телефона» тоже даёт 3 демонстрационных результата.
- «Количество результатов» 5, 10 и 20 дают одинаковую выдачу: демонстрационных записей всего 3.
- Сценарий А4 на КТ1 не проверяется: заглушка не вызывает языковую модель.

**Та же проверка на бэкенде.** Заглушка `POST /search` ведёт себя так же, как мок. С запущенным бэкендом это видно в Swagger: http://127.0.0.1:8000/docs → `POST /search` → Try it out.
