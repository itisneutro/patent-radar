## 2026-11-19 — КТ2: корпус рефератов и формат benchmark

- Бобур — BM25 и RAG:
  - корпус `data/corpus/patents.jsonl`: 200 рефератов патентов РФ на изобретения (вид C1, C2), 8 тем по 25, в каждой теме 3 группы близких патентов; темы, группы, поисковые запросы групп и номера — `data/corpus/groups.json`;
  - скрипт сбора `data/tools/collect_corpus.py`: API поисковой платформы Роспатента, ключ — только переменная окружения `ROSPATENT_TOKEN`, сырые ответы — в кеше `../kt2-raw/` вне репозитория, пауза между запросами не меньше 1 с; страницы реестра ФИПС скрипт не открывает (robots.txt ФИПС), их сверяют вручную;
  - правила записи проверяет `build`: патент РФ на изобретение C1/C2, первый код (51) — из подкласса темы, полный реферат без формул-картинок; если API отдаёт копию реферата из базы DOCDB (длинные обрезаны, индексы потеряны), реферат берётся из исходного XML документа; название — тоже из XML;
  - автоматическая сверка корпуса с двумя ответами API Роспатента — команда `verify`: все 200 записей сравнены с `GET /docs` и XML документа по номеру, виду, названию, всем кодам МПК, году и реферату. Номер, вид, коды МПК и год совпали во всех источниках у всех 200; исправлены по XML 3 названия (в `/docs` пропущены пробелы на месте переноса строки); у 8 записей реферат взят из XML, потому что копия DOCDB в `/docs` обрезана или без индексов; 2 реферата отличаются от XML только тонким пробелом перед надстрочным знаком. Выборочно со страницами ФИПС сверены 4 документа на этапах 0–1;
  - `data/sample/README.md`: как собран корпус, таблицы тем и групп, сверка корпуса; правило нормализации 2 уточнено: первым идёт основной код (51), остальные — в порядке API;
  - `spec/tech/rag.md`: раздел 10.1 — темы, фактическое число записей, группы, как собирали; формат benchmark расширен полем `expected`, описаны `traps.jsonl` и `offtopic.jsonl`; метрики ответов Accuracy и Correct Rejection Rate (раздел 9.1), ловушки и посторонние запросы (раздел 10.7);
  - `benchmark/queries.example.jsonl` — поле `expected`; `benchmark/experiments.py` — проверка поля `expected`, пример запросов проверяется по демо-корпусу.
- Изменён формат benchmark: было `id`, `query`, `relevant`, `topic` → стало `id`, `query`, `relevant`, `topic`, `expected`.
